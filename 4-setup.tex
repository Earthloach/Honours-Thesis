\chapter{A Calculus for Worst-Case Cost Analysis}
\raggedbottom

This Chapter presents $\lambda^g_{\mathsf{worst}}$, a calculus for worst-case cost analysis of guarded recursive programs.
The language's type system consists of the later modality for guarded recursion and a cost monad for cost analysis.
Specifically, the language adapts fragments from the guarded lambda calculus of \cite{cloustonGuardedLambdaCalculusProgramming2017a}
and $\lambda$-amor of \cite{rajaniUnifyingTypetheoryHigherorder2021a}.

Firstly, in Section \ref{sec:cost-foundation} we examine the interaction between gradeds and the later modality, 
which yields the notion of \emph{time-dependent cost}, as a foundation of cost analysis in $\lambda^g_{\mathsf{worst}}$. 
We then describe the syntax, type system, and semantics in Section \ref{sec:worst-case-syntax}, Section \ref{sec:worst-case-type-system}.
Finally, we demonstrate the expressiveness of the calculus through program examples.

\section{Quantative foundations of $\lambda^g_{\mathsf{worst}}$}
\label{sec:cost-foundation}
Following $\lambda$-amor, we use a graded monad to represent cost-aware computations. For example, the type $\tmonad{3}{\tau}$ 
describes a computation whose result has type $\tau$, and the upper bound of the resulting cost is 3. 
More generally, the grade annotation of the monad is a \emph{nonnegative} real number.

Guarded recursion employs a notion of \emph{logical time}, represented by the later modality $\triangleright$ \citep{nakanoModalityRecursion2000}. 
For example, data of type $\tau$ is considered available now, while data of type $\triangleright \tau$ becomes accessible after one time step. 
In other words, an implicit time clock exists at the type level, where entering $\triangleright$ means the clock ticks once.
Therefore, combining with the graded monad, we can leverage this logical time associated with the later modality to express costs that vary each step.

Note that some work presents the clock explicitly \citep{atkeyProductiveCoprogrammingGuarded2013a,mogelberg14, bahrClocksAreTicking2017}, and
multiple clocks can exist, i.e. types like $\triangleright^\alpha$ and $\triangleright^\beta$ where $\alpha, \beta$ denotes 2 different clocks,
thus the notion of time differs between the clocks. 
Following the guarded lambda calculus, we only consider a single global clock in our type system. This also ensures that all costs 
change uniformly as time passes.


\subsection{Time-dependent cost}
Firstly, we use an abstract parameter $i\in\mathbb N$ to denote the current time, starting from $0$. Advancing one time step corresponds to moving from $i$ to $i+1$. 
We aim to specify non-uniform costs that depend on $i$. For instance, a cost of $i+2$ 
gives costs 2, 3, 4 \dots as $i$ advances to $i+1$, $i+2$ \dots, while a constant cost like 3 remains unchanged as $i$ increments.

Similar to $\lambda$-amor, we use an index language to express quantatitive information contained in different types, such as the graded monad.

\begin{defn}(Index)
\label{def:index}
$
  \\
  \begin{aligned}
    I,J ::= {}
    \kappa \mid N \mid R
    \mid I+J \mid I-J
    \mid \textstyle\sum_{\kappa<J} I
    \mid \mathsf{clk}
    \mid \mathsf S^\mathsf{n}(I)
  \end{aligned}
$
\end{defn}

Indices are written as $I$ and $J$, and all indices can depend on the time $i$, below we define the time interpretation of indices.

\begin{defn}(Time interpretations of indices)
\label{def:time-indices}
  \begin{gather*}
    \begin{alignedat}{2}
      \clk(i) &= i
        &\qquad N(i) &= N \\
      R(i) &= R
        &\qquad \kappa(i) &= \kappa \\[0.6em]
      (I-J)(i) &= I(i) - J(i)
        &\qquad (\mathsf{S}^\mathsf{n} I)(i) &= I(i+\mathsf{n})
    \end{alignedat}
    \\[0.8em]
    \begin{aligned}
       (\textstyle\sum_{\kappa<J}I)(i)
        &=\sum_{k=0}^{J(i)-1}I[k/\kappa](i).
    \end{aligned}
  \end{gather*}
\end{defn}
We explain the definitions and interpretations of indices. All indices can be considered as functions from the time 
$i$ to a \emph{nonnegative} real number. The index $\clk$ represents the clock, i.e. the value of the current time $i$. As the clock ticks, $i$ 
increments and the interpretation of $\clk$ changes.

The indices $N, R$ and $\kappa$ represent constant functions on $i$. $N$ is a natural-number constant, $R$ is a \emph{nonnegative} real-number constant, 
and $\kappa$ denotes an index variable. Consequently, their interpretation are all constants, i.e. their original value.
The interpretations of addition and subtraction between indices are defined compositionally.
The $\mathsf{S^n}I$ expression demands the cost when the time is shifted forward by $\mathsf{n}$, then the interpretation of the inner $I$ becomes $I(i+\mathsf{n})$.
We write the shift number as $\mathsf{n}$, meaning that this index is a time-independent constant, and its value is used directly instead of writing $\mathsf{n}(i)$.
$\mathsf{S^n}I$ allows us to express costs that take place in the future.

Finally, the index $\textstyle\sum_{\kappa<J} I$ describes bounded summation over indices, which sums $I$ 
from $0$ to up to $(J(i) - 1)$, where $I$ may have free index variables inside, i.e. $I[0/\kappa] + \ldots + I[(J(i)-1)\kappa]$.  
, and the sum will be $0$ if $J(i)$ is zero.

\subsection{Examples}
Now we can combine the graded monad with the later modality in the type system.
For example, a computation of type $\tmonad{\clk}{\tau}$ produces a \emph{symbolic} cost $\clk$, and the real cost will be the value of 
$i$. If we consider the time starts from 0, then the cost is 0. By contrast, a computation of type $\triangleright\tmonad{\clk}{\tau}$ means that it
will be executed one step later, and the cost will be the value of $i+1 = 1$. 
Likewise, the cost will be $n$ for a computation of type $\triangleright^n \tmonad{\kappa}{\tau}$, where $n$ is the number of nested $\triangleright$.

On the other hand, computations of types $\tmonad{3}{\tau}$ and $\triangleright^n \tmonad{3}{\tau}$ do not distinguish their costs, while only the availabilities of their result data
differ due to the later modality.

\subsection{Indices, Sorts and Constraints}
The index language should be familiar, as described in Section \ref{sec:cost-foundation}. 
Sort determins the range of indices, and indices may belong to two possible sorts: natural numbers $\mathbb{N}$, and 
nonnegative real numbers $\mathbb{R}_{\ge 0}$. Furthermore, $\lambda^g_{\mathsf{worst}}$ has constraint over indices using 
predicates $=$, $<$. There are also conjunction $\land$ and disjunction $\lor$ between indices . 
Since the value of indices depend on the time $i$, predicates are also intepreted by $i$, below we present the interpretation of 
predicates.

\begin{defn}[Interpretation of Predicates]
\label{def:constraint-entailment}
For any two indices $I$ and $J$, we define
\[
\begin{aligned}
  (I < J)
  &\quad\triangleq\quad
  \forall i \in \mathbb{N}.\; I(i) < J(i),\\
  (I = J)
  &\quad\triangleq\quad
  \forall i \in \mathbb{N}.\; I(i) = J(i).
\end{aligned}
\]
\end{defn}

Therefore, predicates are pointwise based on the interpretations of indices.
We do not consider a proof system for constraints in $\lambda^g_{\mathsf{worst}}$, constraints are collected in the 
context $\Delta$, and a constraint $C$ is checked via the context and an abstract validity relation, denoted as $\Delta \models C$.
Thus, we assume a oracle to decide the validity of constraints.
Practically, we can leverage backends such SMT solvers.

\subsection{Types}
$\lambda^g_{\mathsf{worst}}$ contains types in ordinary simply-typed lambda calculus:\ unit, base, function,
product and sum types. Follwing $\lambda$-amor, it also includes types that contains quantatitive informaton.
The list type $L^I \tau$ is refined by length. It carries an index $I$, representing the finite length of the list. Furthermore, the length index is
restricted to be a natural number constant for correctness, and the length should be fixed 
across the time $i$. The graded monad type $\tmonad{I}{\tau}$, as previously mentioned, denotes computations returning data of type $\tau$, producing $I$ cost alongside.
The polymorphic type $\forall\kappa\,{:}S.\tau$ allows type to be parameterised by indices, such as a cost-polymorphic monad
$\forall \kappa:\mathbb{N}.\;\tmonad{\kappa}{\tau}$.


Based on the guarded lambda calculus, $\lambda^g_{\mathsf{worst}}$ also includes the modal type $\triangleright \tau$ alongside the recursive type $\mu \alpha.\tau$ to 
express guarded recursion.


Compared to $\lambda$-amor, we retain universal index quantification, as $\forall\kappa\,{:}S.\tau$, 
while omitting its additional existential index quantification and quantification over types for simplicity. 
In addition, $\lambda$-amor is a refinement type system that incorporates constraint types to ensure certain constraints holds at type level. 
However, we find using constraints for type and subtype formations is enough for $\lambda^g_{\mathsf{worst}}$, and thus drop constraint types.

\subsection{Terms}
Expressions defined in Figure \ref{def:worst-case-syntax} covers all forms of terms, containing constructors and destructors for types.
Most terms are common in simply-typed lambda calculus and should be familiar. 
The applicative functor operations of the later type \citep{mcbrideP08}, which is $\delay$ and $\circledast$ in $\lambda^g_{\mathsf{worst}}$.
The $\delay$ constructor introduces a term of the later type, and the $\circledast$ operator composes two terms of later type as function application.
indexed lists have the constructors $nil$ and cons "$::$", with a pattern matching as the elimination form.
We use iso-recursive types in $\lambda^g_{\mathsf{worst}}$, a recursive type and its unfolding are isomorphic.
The $\fold$ and $\unfold$ are standard operators that map iso-recursive types and its unfoldings to each other.
Universal index quantifiers are introduced by $\Lambda.e$ and eliminated by $e\;[\,]$.
Follwing $\lambda$-amor, index variables do not occur in terms, thus the bound index variable in type abstraction and the instantiating index in type application
are omitted.

There are several constructors for the monadic type $\tmonad{I}{\tau}$, including the standard unit and bind operation of monads: $\ret e$ and $\bind{x}{e_1}{e_2}$.
The tick operator ($\tick{I}$) is an atomic operation for incurring a symbolic cost of $I$.
Additionally, the $\pull$ operator takes a delayed computation, specifically, a term of type $\triangleright \tmonad{I}{\tau}$,
executes the future cost and returning the delayed result. The $\pull$ combinator distributes the later modality and the graded monad, and we will 
further discuss it in the next section.

The judgment for indices is in the form $\Theta;\Delta\vdash I: S$, where $S$ is the sort of the index $I$, $\Theta$ is the context that maps index variables $\kappa$ to their sorts, and 
$\Delta$ is the context that contains constraints about indices. Constraints in $\Delta$ may refer to varibles in $\Theta$, therefore we need to couple them together.

Figure \ref{defn:worst-case-sort-rule} presents the sort rules for indices. The \textsc{S-Var, S-Nat}  and \textsc{S-Real} rules are standard. 
The $\mathsf{clk}$ expression is treated as a natural number, representing the logical time. For ordinary arithmetic operations, we require
both arguments to have the same sort. Since indices cannot be negative according to all the sorts ($\mathbb{N}, \mathbb{R}_{\ge0}$), subtraction $I - J$ needs to
ensure that $J \leq I$, here we write $J \leq I$ as the disjunction between $J < I$ and $J = I$. Similarly in \text{S-Sum}, we ensure the index variable to be smaller than the bound $I$ when checking 
the body expression. The \textsc{S-NatReal} rule casts a natural number expression into a nonnegative real number, this premits us to use a natural number as the same real number. 
Finally, the \textsc{S-Shift} rule shifts the time of the body, the shift value $\mathsf{n}$ needs to be a natural number constant. Since constraints are pointwise, 
the predicate $\mathsf{n} = \mathsf{S(n)}$ holds for every time, i.e. $\forall i \in \mathbb{N}, \mathsf{n}(i) = \mathsf{S(n)}(i)$, ensuring that $\mathsf{n}$ does not change across the time, 
then each shift only incrments a fixed amount of time.

$\Psi$ is the context that contains a set of type variables, mainly used for the variable $\alpha$ in the recursive type $\mu \alpha.\tau$.
Most rules are straightforward and compositional, where the rules are specified by each part of a type.
We also need the contexts $\Theta$ and $\Delta$ to check sorts and constraints since types can mention indices.
Specifically, the \textsc{WF-Monad} rule requires the cost index to be a nonnegative real number; in the \textsc{WF-List} rule, we need to ensure that the 
length of the list remain fixed acorss the time by the constraint $I = \mathsf{S}(I)$, which is similar to that in the \textsc{S-Shift} rule.

\textsc{WF-Rec} is a crucial rule in the type system. A type variable $\alpha$ is \emph{guarded} in a type $\tau$ if each
occurrence of it in $\tau$ is beneth of a later modality $\triangleright$. This brings guarded recursion, where all self-refrences in the recursive type need to be 
guarded.

\subsection{Subtyping}
Subtyping is an important part of our type system, in particular, it allows a cost bound to be weakened in our type system.

The subtyping judgment is $\Theta;\Delta\vdash\tau<:\tau'$, similar to type well-formedness, it requires $\Theta$ and $\Delta$ to ensure constraints hold for certain rules. 
We follow $\lambda$-amor and the usual treatment of subtyping: the relation $<:$ is a preorder on types, it satisfies reflexivity and transitivity. These two 
properties are captured by the \textsc{Sub-Refl} rule and the \textsc{SubTrans} rule. The \textsc{Sub-Arrow} rule is standard, where it is contravariant in its argument type, i.e.
the order for arguments $\tau_1' <: \tau'$ is the reverse of that for the whole type $\tau_1 \to \tau_2 <: \tau_1' \to \tau_2'$.

The \textsc{Sub-Monad} rule gives the subtyping relation for the cost monad, a monad $\tmonad{I}{\tau}$ can be treated as 
$\tmonad{I'}{\tau'}$ if $\tau <: \tau'$ and $I \leq I'$. As a result, the cost bound of a type can be increased, this is sound because costs are upper bounds, 
we can safely execute a computation that incurs less cost than it is originallly expected.

Subyping recursive types is a crucial and complicated task, and we impose a restriction on it. 
Before describing the \textsc{Sub-Rec} rule, we first define \emph{positive} and \emph{negative} occurrences of types, based on \cite{pierce02}.

\pagebreak

\begin{defn}
\label{def:polarity}
The \emph{positive} and \emph{negative occurrences} in a type $\tau$
are defined inductively:
\begin{enumerate}
  \item $\tau$ is a positive occurrence in $\tau$.
  \item If $\tau_1 \to \tau_2$ is a positive occurrence in $\tau$, then
        $\tau_1$ is a negative occurrence in $\tau$ and $\tau_2$ is a
        positive occurrence in $\tau$.
  \item If $\tau_1 \to \tau_2$ is a negative occurrence in $\tau$, then
        $\tau_1$ is a positive occurrence in $\tau$ and $\tau_2$ is a
        negative occurrence in $\tau$.
  \item If any of $\tau_1 \times \tau_2$, $\tau_1 + \tau_2$,
        $L^n\,\tau_1$, $\triangleright\tau_1$, $\mathbb{M}\,I\,\tau_1$,
        $\forall\kappa{:}S.\,\tau_1$ or $\mu\alpha.\tau_1$ is a
        positive occurrence in $\tau$, then each of its immediate
        component types is a positive occurrence in $\tau$.
  \item If any of the types in (4) is a negative occurrence in $\tau$,
        then each of its component types is a negative occurrence
        in $\tau$.
\end{enumerate}
\end{defn}

We say that a type variable $\alpha$ is \emph{positive} in $\tau$ if all free occurrences of it in $\tau$ are positive, i.e. no negative occurrences of $\alpha$ in $\tau$.
For example, the variable $\alpha$ is positive in $\textbf{1} \to \alpha$, $L^n\,\alpha \times \textbf{1}$, and negative in $\alpha \to \textbf{1}$.

The subtyping relation does not always hold after unfolding two related iso-recursive types due to negative occurrences, we follow an example adaptd from \cite{zhouRevisitingIsorecursiveSubtyping2020}.
If we ignore the postivie side condition from \textsc{S-Rec}, we can derive the following relation:
\[\mu \alpha.(\triangleright\alpha) \to \tmonad{0}{\textbf{1}} <: \mu \alpha.(\triangleright\alpha) \to \tmonad{1}{\textbf{1}} \qquad (1)\]
Unfold the types on each side, we get
\[
  \triangleright\big(\mu \alpha.(\triangleright\alpha)\to\tmonad{0}{\textbf{1}}\big)\to\tmonad{0}{\textbf{1}} 
  <:
  \triangleright\big(\mu \alpha.(\triangleright\alpha)\to\tmonad{1}{\textbf{1}}\big)\to\tmonad{1}{\textbf{1}} 
\]
However, this relation does not hold. From \textsc{Sub-Arrow}, checking the argument types requires a reverse of (1):
\[\mu \alpha.(\triangleright\alpha) \to \tmonad{1}{\textbf{1}} <: \mu \alpha.(\triangleright\alpha) \to \tmonad{0}{\textbf{1}}\]
This is invalid since $\tmonad{1}{\textbf{1}}$ is not a subtype of $\tmonad{0}{\textbf{1}}$.

Although the preservation of subtyping is not necessary for iso-recursive types, it is a desired property needed for the metatheory of 
$\lambda^g_{\mathsf{worst}}$ presented in the next Chapter.

The major limitation of restricting negative ooccurrences in the \textsc{Sub-Rec} rule, is that it rejects all negative subtyping. However, most recursive types considered in 
$\lambda^g_{\mathsf{worst}}$ like streams only have postive occurrences. There are also alternatives, such as the Amber rules \citep{cardelli85}, which are used commonly for
recursive subtyping. The Amber rules are more powerful since it allows subtyping for some types that includes negative occurrences, while those types are usually not concerned in our type system, we
choose to adopt the simple restriction approach.

\subsection{Terms and Typing judgments}
The typing judgment for terms in $\lambda^g_{\mathsf{worst}}$ is written as $\hastype{\Theta;\Delta;\Gamma}{e}{\tau}$. 
$\Gamma$ is the context that maps term variables $e$ to their types, and we need the context $\Theta$ and $\Delta$ as usual.
Since type variables only appear in recursive types, and type substitution is used directly for unfolding, therefore we do not need the $\Psi$ context to 
record type variables. The typing rules are listed in Figure \ref{def:worst-case-typing-judgment}. 

Most rules are standard for introduction and elimination forms of terms. 
\textsc{T-Nil} is the rule for the term $nil$ that introduces a empty list, then the type is $L^0 \tau$.
\textsc{T-Cons} describes the typing for the cons expression $"::"$ that pushes an new element in the front of a list, and the length index of the resulting list 
needs to increase by one. Consequently, pattern matching on a list has two branches, where the list is either $nil$ or cons, and the list have different lengths in each case.
Thus, the \textsc{T-Cons} rule adds corresponding constraints: length $I = 0$ and $I > 0$ for each branch.
\textsc{T-Fold} and \textsc{T-Unfold} are the two rules that substitutes type variables bounded by the recursive type.
Likewise, the term-level index instantiation $e\;[\,]$ requires substituting index variable as the result type $\tau [I/\kappa]$.

The rules for cost analysis are more interesting. $\ret e$ lifts a pure term $e$ typed $\tau$ into a monadic computation,
it does not modify $e$ and incur any cost, hence the type is $\tmonad{0}{\tau}$. 
The monadic bind sequences two computations and sums their costs, as described by the \textsc{T-Bind} rule.
\textsc{T-Tick} is the rule for the $\tick{I}$ computation, it gives a result of the unit type and produces $I$ units of cost.
The \textsc{T-Pull} rule typechecks the $\pull e$ term, it distributes the later modality and the graded monad, pulling the 
delayed monad out and keeps the inner result only available in the future. Since we intend to pay the future cost in advance, 
the cost becomes $\mathsf{S}(I)$, here we write $\mathsf{S}(I)$ as $\mathsf{S}^1(I)$, meaning that it is calculated by incrementing the time clock once.

Finally, \textsc{T-Sub} connects subtyping with terms.
The \textsc{T-Weaken} rule uses the subtyping relation $<:$ between typing contexts.
The subtyping judgment $\Theta;\Delta\vdash \Gamma <: \Gamma$ is defined inductively, the rules are listed in Figure \ref{def:worst-case-context-sub}, where
$\cdot$ represents the empty context in the base case. Intuitively, a context $\Gamma'$ can be replaced by another context $\Gamma$ that 
may contain extra variables or supertypes, which is analogous to record subtyping.
