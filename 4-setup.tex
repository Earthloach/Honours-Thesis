This chapter presents $\lambda^g_{\mathsf{worst}}$, a calculus for worst-case cost analysis of guarded recursive programs.
The type system combines the later modality for guarded recursion with a graded monad for cost analysis.
Specifically, the calculus adapts fragments from the guarded lambda calculus of \cite{cloustonGuardedLambdaCalculusProgramming2017a}
and $\lambda$-amor of \cite{rajaniUnifyingTypetheoryHigherorder2021a}.

Firstly, in Section \ref{sec:cost-foundation} we examine how the interaction between grades and the later modality yields the notion of \emph{time-dependent cost}, 
the foundation of cost analysis in $\lambda^g_{\mathsf{worst}}$. 
We then present the syntax, type system, and operational semantics in
Sections \ref{sec:worst-case-syntax}, \ref{sec:worst-case-type-system},
and \ref{sec:worst-case-semantics}.
Finally, Section \ref{sec:worst-case-program-examples} illustrates the calculus with examples of cost analysis for guarded recursive programs.

\section{Foundations of cost}
\label{sec:cost-foundation}
Following $\lambda$-amor, we use a graded monad to represent cost-aware computations. For example, the type $\tmonad{3}{\tau}$ 
describes a computation whose result has type $\tau$, and the upper bound of the resulting cost is 3. 
More generally, the grade annotation of the monad is a \emph{nonnegative} real number.

Guarded recursion employs a notion of \emph{logical time}, represented by the later modality $\triangleright$ \citep{nakanoModalityRecursion2000}. 
For example, data of type $\tau$ is considered available now, while data of type $\triangleright \tau$ becomes accessible after one time step. 
In other words, an implicit time clock exists at the type level, where entering $\triangleright$ means the clock ticks once.
Combining with the graded monad, we can leverage this logical time to express costs that vary each step.

Note that some work presents the clock explicitly \citep{atkeyProductiveCoprogrammingGuarded2013a,mogelberg14, bahrClocksAreTicking2017}, and
multiple clocks can exist, e.g. types like $\triangleright^\alpha$ and $\triangleright^\beta$ where $\alpha, \beta$ denotes 2 different clocks,
thus, the notion of time differs between the clocks. 
Following the guarded lambda calculus, we only consider a single global clock in our type system. This also ensures that all costs 
change uniformly as time passes.

\subsection{Time-dependent Cost}
Firstly, we use an abstract parameter $i\in\mathbb N$ to denote the current time. Advancing one time step corresponds to moving from $i$ to $i+1$. 
Our aim is to specify non-uniform costs that change with $i$. For instance, if $i$ starts at zero, a cost of $i+2$ 
gives costs 2, 3, 4 \dots as $i$ advances to $i+1$, $i+2$ \dots, while a constant cost like 3 remains unchanged as $i$ increments.

Similar to $\lambda$-amor, we use an index language to express quantitative information contained in different types, such as the graded monad.

\begin{defn}(Index)
\label{def:index}
$
  \\
  \begin{aligned}
    I,J ::= {}
    \kappa \mid N \mid R
    \mid I+J \mid I-J
    \mid \textstyle\sum_{\kappa<J} I
    \mid \mathsf{clk}
    \mid \mathsf{S}^J(I)
  \end{aligned}
$
\end{defn}

Indices are written as $I$ and $J$, they represent \emph{symbolic} costs that can be instantiated by $i$. Below we define the time interpretation of indices.

\begin{defn}(Time interpretations of indices)
\label{def:time-indices}
  \begin{gather*}
    \begin{alignedat}{2}
      \clk(i) &= i
        &\qquad N(i) &= N \\
      R(i) &= R
        &\qquad \kappa(i) &= \kappa \\[0.6em]
      (I-J)(i) &= I(i) - J(i)
        &\qquad (\mathsf{S}^J I)(i) &= I(i+J)
    \end{alignedat}
    \\[0.8em]
    \begin{aligned}
       (\textstyle\sum_{\kappa<J}I)(i)
        &=(\sum_{k=0}^{J-1}I[k/\kappa])(i).
    \end{aligned}
  \end{gather*}
\end{defn}
All indices can be considered as functions from the time 
$i$ to a \emph{nonnegative} real number. The index $\clk$ represents the clock, i.e. the value of the time $i$. As the clock ticks, $i$ 
increments and the interpretation of $\clk$ changes. In addition, $i$ can be regarded as a Kripke world, where indices get their corresponding values at current world.

The indices $N, R$ and $\kappa$ represent constant functions on $i$. $N$ is a natural-number constant, $R$ is a \emph{nonnegative} real-number constant, 
and $\kappa$ denotes an index variable. Consequently, their interpretations follow their original values.
The interpretations of addition and subtraction between indices are defined compositionally.
The $\mathsf{S}^{J}I$ index denotes the cost $I$ when the time is shifted forward by $J$, then the interpretation of the inner $I$ becomes $I(i+J)$.
We write the shift value directly using $J$ instead of $J(i)$, 
meaning that $J$ is a constant whose interpretation is always itself, and $J$ is restricted to be a natural number.
Intuitively, $\mathsf{S}^JI$ allows us to express costs that take place in the future.

Finally, the index $\textstyle\sum_{\kappa<J} I$ represents bounded summation that sums $I$ 
from $0$ up to $(J - 1)$. In particular, $I$ can contain the variable $\kappa$ bound by the sum, and $J$ needs to be a natural number constant. Therefore, the symbolic costs can be summed directly, 
i.e. $I[0/\kappa] + \ldots + I[(J-1)/\kappa]$ or $\sum_{k=0}^{J-1}I[k/\kappa]$.
Moreover, the sum will simply be $0$ if $J$ is zero.

\subsection{Examples}
Now we can combine the graded monad with the later modality in the type system.
For example, a computation of type $\tmonad{\clk}{\tau}$ produces a \emph{symbolic} cost $\clk$, and the real interpreted cost will be the value of 
$i$. If we consider the time starts from 0, then the cost is 0. By contrast, a computation of type $\triangleright\tmonad{\clk}{\tau}$ means that it
will be executed one step later, and the cost will be the value of $i+1 = 1$. 
Likewise, the cost will be $n$ for a computation of type $\triangleright^n \tmonad{\kappa}{\tau}$, where $n$ is the number of nested $\triangleright$ types. 
For a clearer illustration, Table \ref{fig:ticktime-costs} lists the cost sequence of a guarded stream whose elements are typed $\tmonad{\clk}{\tau}$.

In contrast, computations of types $\tmonad{3}{\tau}$ and $\triangleright^n \tmonad{3}{\tau}$ do not distinguish their costs.

\section{Syntax}
\label{sec:worst-case-syntax}
In this section, we present the full syntax of $\lambda^g_{\mathsf{worst}}$, providing a general description of the surface constructs included in the calculus.
Since the calculus combines part of $\lambda$-amor and the guarded lambda calculus, the formalisation is similar.

\subsection{Indices, Sorts and Constraints}
The index language should be familiar, as described in Section \ref{sec:cost-foundation}. 
Sort determines the range of indices, and indices may belong to two possible sorts: natural numbers $\mathbb{N}$, and 
nonnegative real numbers $\mathbb{R}_{\ge 0}$. Furthermore, $\lambda^g_{\mathsf{worst}}$ has constraint over indices using 
predicates $=$, $<$. There are also conjunction $\land$ and disjunction $\lor$ between constraints. 
Since indices depend on the time $i$, predicates are determined by $i$ as well. The interpretation of predicates is defined as below:
\begin{defn}[Interpretation of Predicates]
\label{def:constraint-entailment}
For any two indices $I$ and $J$, we define
\[
\begin{aligned}
  (I < J)
  &\quad\triangleq\quad
  \forall i \in \mathbb{N}.\; I(i) < J(i),\\
  (I = J)
  &\quad\triangleq\quad
  \forall i \in \mathbb{N}.\; I(i) = J(i).
\end{aligned}
\]
\end{defn}

From Definition \ref{def:time-indices} and the pointwise interpretation of predicates, we can easily derive equalities about the shift operation: For any index $I$, $\mathsf{S}^0 I= \mathsf{S}I$, 
and for any natural number constant indices $J, K$, $\mathsf{S}^J(\mathsf{S}^KI) = \mathsf{S}^{J+K}I$.
In addition, the shift operation distributes over standard arithmetic expressions:
\begin{lem}[Distributivity of Shift]
\label{lem:shif-dist}
For any well-formed indices $I, J$, and $K$, if $ K$ is a natural number constant, then the following equalities hold:
\begin{align*}
  &(1) \qquad \mathsf{S}^K(I+J)
  = \mathsf{S}^K(I)+\mathsf{S}^K(J),\\
  &(2)\qquad \mathsf{S}^K(I-J)
  = \mathsf{S}^K(I)-\mathsf{S}^K(J),\\
  &(3)\qquad \text{If } J \text{ is a natural number constant}, \text{ then }\mathsf{S}^K\left(\textstyle\sum_{\kappa<J}I\right)
  = \textstyle\sum_{\kappa<J}\mathsf{S}^K(I).
\end{align*}
\end{lem}
\begin{proof}
  See Lemma \ref{appa:shift-dist}
\end{proof}

We do not fix a proof system for constraints in $\lambda^g_{\mathsf{worst}}$. Instead, we use a context $\Delta$ to collect constraints, and an abstract validity relation $\Delta \models C$ states that $C$ follows from $\Delta$. 
Thus, all constraint reasoning is delegated to an oracle, which in practice can be implemented by a backend such as an SMT solver. 
The next section shows how this relation is used for type formations.

\subsection{Types}
$\lambda^g_{\mathsf{worst}}$ contains types in ordinary simply-typed lambda calculus:\ unit, base, function,
product and sum types. Following $\lambda$-amor, we also include types that contain quantitative information.
The list type $L^I \tau$ carries an index $I$, representing its finite length. Furthermore, the length index is
restricted to be a natural number constant for correctness. The graded monad $\tmonad{I}{\tau}$, as previously mentioned, denotes computations returning data of type $\tau$, producing $I$ units of symbolic cost.
The polymorphic type $\forall\kappa\,{:}S.\tau$ allows types to be parameterised by indices, such as a cost-polymorphic monad
$\forall \kappa:\mathbb{N}.\;\tmonad{\kappa}{\tau}$.

Based on the guarded lambda calculus, $\lambda^g_{\mathsf{worst}}$ also includes the modal type $\triangleright \tau$ and the recursive type $\mu \alpha.\tau$ to achieve guarded recursion.

For simplicity, we omit $\lambda$-amor's existential index quantification and quantification over types. 
In addition, $\lambda$-amor incorporates constraint types to ensure certain constraints hold for programs. 
However, we find that using constraints for type and subtype formations is enough for $\lambda^g_{\mathsf{worst}}$.

\subsection{Terms}
Expressions defined in Figure \ref{def:worst-case-syntax} covers all forms of terms in $\lambda^g_{\mathsf{worst}}$.
Most terms are common in simply-typed lambda calculus and should be familiar. 
$\delay$ and $\circledast$ are the applicative functor operations of the later type \citep{mcbrideP08}.
The $\delay$ constructor introduces a term of the later type, and the $\circledast$ operator composes two terms of later type as a function application.
Lists have the constructors $nil$ and cons ``::'', with pattern matching as the eliminator.

We use iso-recursive types in $\lambda^g_{\mathsf{worst}}$, where a recursive type and its unfolding are isomorphic.
This is achieved by the $\fold$ and $\unfold$ operators, mapping recursive types and their unfoldings to each other.
Universal index quantification is introduced by the index abstraction $\Lambda.e$ and eliminated by the application $e\;[\,]$.
Observe that index variables are omitted for them, this follows from $\lambda$-amor, where index variables cannot occur in terms.

There are several constructors for the type $\tmonad{I}{\tau}$, including the standard unit and bind operation of monads: $\ret e$ and $\bind{x}{e_1}{e_2}$.
The tick operator ($\tick{I}$) is the atomic operation for incurring a symbolic cost of $I$.
The $\pull$ operator takes a delayed computation, specifically, a term of type $\triangleright \tmonad{I}{\tau}$,
executes the future cost and returns the delayed result. Crucially, $\pull$ distributes over the later modality and the graded monad, and we will 
further discuss it in the next section.

  \label{defn:worst-case-sort-rule}
\end{figure}

The judgment for indices is in the form $\Theta;\Delta\vdash I: S$, where $\Theta$ is the context that maps index variables $\kappa$ to their sorts $S$, and 
$\Delta$ is the context that contains constraints about indices as mentioned previously. Constraints in $\Delta$ may refer to variables in $\Theta$, we thus need to use them together.

Figure \ref{defn:worst-case-sort-rule} presents the sort rules for indices. The \textsc{S-Var, S-Nat}  and \textsc{S-Real} rules should be self-explanatory. 
The $\mathsf{clk}$ expression is treated as a natural number, representing the logical time. The \textsc rule allows a natural number index to be used as a nonnegative real number with the same value. 
For ordinary arithmetic operations, we require
both arguments to have the same sort. Since indices cannot be negative according to all the sorts ($\mathbb{N}, \mathbb{R}_{\ge0}$), the subtraction $I - J$ needs to
ensure that $J \leq I$. Here we write $J \leq I$ as the disjunction between $J < I$ and $J = I$. Similarly, in \text{S-Sum}, we ensure the index variable is smaller than the bound $I$ when checking 
the body expression. Moreover, we restrict the bound $J$ to be a natural number constant, checked by the constraint:
$J = \mathsf{S}(J)$. Since constraints are pointwise to the time, this ensures $J$'s interpretation does not change for any $i$.
Finally, the \textsc{S-Shift} rule shifts the time to interpret the body expression. Again, the index $J$ is restricted to be a constant through the same constraint of \textsc{S-Sum}
ensuring that the shift only increments a fixed amount of time.

Figure \ref{def:worst-case-type-well-form} shows the type well-formedness rules; these rules specify how types are formed correctly in $\lambda^g_{\mathsf{worst}}$.
$\Psi$ is the context that contains a set of type variables.  When checking a recursive type $\mu\alpha.\tau$, the context is extended with $\alpha$ to ensure that occurrences of this variable in $\tau$ are well-formed.
We also need the contexts $\Theta$ and $\Delta$ to check sorts and constraints since types can mention indices.
In particular, the \textsc{WF-Monad} rule requires the cost index to be a nonnegative real number; in the \textsc{WF-List} rule, we need to ensure that the 
length of the list remains fixed across time by the constraint $I = \mathsf{S}(I)$ described before.

\textsc{WF-Rec} is a crucial rule in the type system. A type variable $\alpha$ is \emph{guarded} in a type $\tau$ if each
occurrence of it in $\tau$ is beneath a later modality. This brings guarded recursion, where all self-references in the recursive type need to be 
guarded.

\subsection{Subtyping}
Subtyping is an important part of our type system, in particular, it allows a cost bound to be weakened in our type system. 
Figure \ref{def:worst-case-subtyping} gives the subtyping rules.

The subtyping judgment is $\Theta;\Delta\vdash\tau<:\tau'$, similar to the type well-formedness judgment, it requires $\Theta$ and $\Delta$ to ensure constraints hold for certain rules. 
We follow $\lambda$-amor and the usual treatment of subtyping: the relation $<:$ is a preorder on types that satisfies reflexivity and transitivity. These two 
properties are captured by \textsc{Sub-Refl} and \textsc{SubTrans}. The \textsc{Sub-Arrow} rule follows the standard, where it is contravariant in its argument type, i.e.
the order for arguments $\tau_1' <: \tau'$ is the reverse of that for the whole type $\tau_1 \to \tau_2 <: \tau_1' \to \tau_2'$.

The \textsc{Sub-Monad} rule gives subtyping for the cost monad, a monad $\tmonad{I}{\tau}$ can be treated as 
$\tmonad{I'}{\tau'}$ if $\tau <: \tau'$ and $I \leq I'$. As a consequence, the cost bound of a type can be increased, this is sound because costs are upper bounds. We can safely execute a computation that incurs a lower cost than it is originally expected.

Subyping recursive types is a crucial and complicated task, and we impose a restriction on it. 
To explain the \textsc{Sub-Rec} rule, we first define \emph{positive} and \emph{negative} occurrences of types, based on \cite{pierce02}.

\Needspace{7\baselineskip}
\begin{defn}
\label{def:polarity}
The \emph{positive} and \emph{negative occurrences} in a type $\tau$
are defined inductively:
\begin{enumerate}
  \item $\tau$ is a positive occurrence in $\tau$.
  \item If $\tau_1 \to \tau_2$ is a positive occurrence in $\tau$, then
        $\tau_1$ is a negative occurrence in $\tau$ and $\tau_2$ is a
        positive occurrence in $\tau$.
  \item If $\tau_1 \to \tau_2$ is a negative occurrence in $\tau$, then
        $\tau_1$ is a positive occurrence in $\tau$ and $\tau_2$ is a
        negative occurrence in $\tau$.
  \item If any of $\tau_1 \times \tau_2$, $\tau_1 + \tau_2$,
        $L^n\,\tau_1$, $\triangleright\tau_1$, $\mathbb{M}\,I\,\tau_1$,
        $\forall\kappa{:}S.\,\tau_1$ or $\mu\alpha.\tau_1$ is a
        positive occurrence in $\tau$, then each of its
        component types is a positive occurrence in $\tau$.
  \item If any of the types in (4) is a negative occurrence in $\tau$,
        then each of its component types is a negative occurrence
        in $\tau$.
\end{enumerate}
\end{defn}

We say that a type variable $\alpha$ is \emph{positive} in $\tau$ if all free occurrences of it in $\tau$ are positive, i.e. no negative occurrences of $\alpha$ in $\tau$.
For example, the variable $\alpha$ is positive in $\textbf{1} \to \alpha$, $L^n\,\alpha \times \textbf{1}$, and negative in $\alpha \to \textbf{1}$.

Due to negative occurrences, the subtyping relation does not always hold after unfolding two related recursive types, we adapt an example from \cite{zhouRevisitingIsorecursiveSubtyping2020} to our setting:
Suppose dropping the positive side condition from \textsc{S-Rec}, we can derive the following relation:
\[\mu \alpha.(\triangleright\alpha) \to \tmonad{0}{\textbf{1}} <: \mu \alpha.(\triangleright\alpha) \to \tmonad{1}{\textbf{1}} \qquad (1)\]
Unfolding the types on each side, we have
\[
  \triangleright\big(\mu \alpha.(\triangleright\alpha)\to\tmonad{0}{\textbf{1}}\big)\to\tmonad{0}{\textbf{1}} 
  <:
  \triangleright\big(\mu \alpha.(\triangleright\alpha)\to\tmonad{1}{\textbf{1}}\big)\to\tmonad{1}{\textbf{1}} 
\]
However, this relation does not hold. From \textsc{Sub-Arrow}, checking the argument types requires a reverse of (1):
\[\mu \alpha.(\triangleright\alpha) \to \tmonad{1}{\textbf{1}} <: \mu \alpha.(\triangleright\alpha) \to \tmonad{0}{\textbf{1}}\]
This is invalid since $\tmonad{1}{\textbf{1}}$ is not a subtype of $\tmonad{0}{\textbf{1}}$.

Although the preservation of subtyping is not necessary for iso-recursive types, it is a desired property needed for the meta-theory of 
$\lambda^g_{\mathsf{worst}}$ presented in the next chapter.

The major limitation of restricting negative occurrences in the \textsc{Sub-Rec} rule is that it rejects all negative subtyping. However, most recursive types considered in 
$\lambda^g_{\mathsf{worst}}$ like streams only have positive occurrences. An alternative approach is the Amber rules \citep{cardelli85}, which are commonly used for recursive subtyping. These rules are more permissive, allowing certain negative occurrences of recursive type variables. Nevertheless,  those cases are usually not concerned in our type system, we
choose to adopt the simple restriction approach.

Since type variables only appear in recursive types, and type substitution is used directly for unfolding, therefore we do not need the $\Psi$ context to

The typing rules are presented in Figure \ref{def:worst-case-typing-judgment}. Most rules are standard, corresponding to the introduction and elimination rules for the respective type constructors.
\textsc{T-Nil} is the rule for the term $nil$ that introduces an empty list, thus, the type is $L^0 \tau$.
\textsc{T-Cons} describes the typing for the cons (::) expression which pushes a new element in front of a list, and the length index of the resulting list 
needs to increase by one. Consequently, pattern matching on a list has two branches, where the list is either $nil$ or cons.
The \textsc{T-Match} rule also adds more assumptions to refine existing constraints: length $I = 0$ and $I > 0$ for the corresponding branch.
\textsc{T-Fold} and \textsc{T-Unfold} are the two rules that substitutes type variables bounded by the recursive type.
Likewise, the term-level index instantiation $e\;[\,]$ requires substituting index variable as the result type $\tau [I/\kappa]$.

The rules for cost analysis are more interesting. $\ret e$ lifts a pure term $e$ typed $\tau$ into a monadic computation,
it does not modify $e$ and incur any cost, hence the type is $\tmonad{0}{\tau}$. 
The monadic bind sequences two computations and sums their costs, as described by the \textsc{T-Bind} rule.
\textsc{T-Tick} is the rule for the $\tick{I}$ operation, it returns a result of the unit type and produces the cost $I$.
The \textsc{T-Pull} rule type-checks the $\pull e$ term, it distributes the later modality and the graded monad, pulling the 
delayed monad out and keeps the inner result available in the future. Since we intend to pay the future cost in advance, 
the cost becomes $\mathsf{S}(I)$, here we write $\mathsf{S}(I)$ as $\mathsf{S}^1(I)$, meaning that it is calculated by shifting the time forward once.

In the end, \textsc{T-Sub} connects subtyping with terms, and the \textsc{T-Weaken} rule uses the subtyping relation $<:$ between typing contexts.
The subtyping judgment $\Theta;\Delta\vdash \Gamma <: \Gamma$ is defined inductively, where the rules are listed in Figure \ref{def:worst-case-context-sub}, where
$\cdot$ represents the empty context in the base case. As a result, a context $\Gamma'$ can be replaced by another context $\Gamma$ that 
may contain extra variables with possibly their subtypes, which is analogous to record subtyping.

\section{Semantics}
\label{sec:worst-case-semantics}
In this section, we present the big-step, call-by-value operational semantics of $\lambda^g_{\mathsf{worst}}$.
Usually, the semantics should relate a term $e$ to a value (normal form) defined in a calculus, we first discuss the definition of values in $\lambda^g_{\mathsf{worst}}$ and connect it to
the semantics.

\subsection{Values}
The judgment $e\;\mathsf{val}_n$ states that the term $e$ is a value at "depth $n$".
The intuition is that all recursive definitions of terms will be guarded by a $\delay$ constructor, just like recursive types are guarded by a $\triangleright$, then we may get 
infinite nested $\delay$ constructors for recursions. Evaluation must look inside
$\mathsf{next}$ to produce anything beyond the current step. We therefore bound the number of nested
$\mathsf{next}$ constructors it may enter by a natural number $n$.
A value at depth $n$ is thus a finite
prefix of a possibly infinite result.

Figure \ref{def:values} gives the value judgments. The judgments of most constructors are defined compositionally by their components. 
For instance, \textsc{V-Pair} states that $\tuple{e_1}{e_2}$ is a value when both $e_1$ and $e_2$ are values. \textsc{V-Constant} specifies terms that are considered directly as values no matter the value of $n$.
Monads are lazy, hence their constructors are treated as values directly.

The judgment for $\mathsf{next}\,e$ is defined by induction on $n$: at depth $0$,
$\mathsf{next}\,e$ is a value for any term $e$, and at depth $n+1$
it is a value when $e$ is a value at depth $n$. Once the depth reaches
$0$, terms inside a $\delay$ are considered as being suspended, hence they are accepted as values without inspecting their content.

Intuitively, if a term is a value at depth $n$, it is also a value at a smaller depth.

\begin{lem}[Monotonicity of Values]
\label{lem:worst-case-value-closure}
$\\$ For any $e$, and $m, n \in \mathbb{N}$, if $\isval{e}{n}$ and $m\leq n$, then $\isval{e}{m}$.
\end{lem}
\begin{proof}
  Induction on the derivation of $\isval{e}{n}$, we present the two cases related to $\delay e$.
  % The \textsc{V-Stable} case is immediate; the cons, pair, inl, inr, and
  % fold cases follow by the IH. For \textsc{V-NextZero}, necessarily $m=0$.
  \begin{itemize}
    \item Case \textsc{V-NextBase}: since $n$ is 0, then $m = 0$, and we have the goal directly.
    \item Case \textsc{V-NextInd}: let $n=k+1$ and $e=\delay e_0$, with
    $\isval{e_0}{k}$. If $m=0$, we get the desired by \textsc{V-NextZero}. Otherwise,
    let $m=r+1$ with $r\leq k$, applying the IH with $e_0, r, k$ gives
    $\isval{e_0}{r}$. By \textsc{V-NextSucc}, we have $\isval{(\delay e_0)}{m}$. \qedhere
  \end{itemize}
\end{proof}



\subsection{Evaluation}
Following $\lambda$-amor, $\lambda^g_{\mathsf{worst}}$ includes two kinds of semantics: pure evaluation for pure terms and forcing evaluation for monadic computations.

\subsubsection{Pure Evaluation}
The pure evaluation judgment is defined as $e \Downarrow_n v$, evaluating a pure term into a value, without incurring any cost. For convenience, we write $v$ to denote a term that satisfies the value judgment at the depth $n$.
Operationally, one can also think of the index $n$ as the amount of fuel
available to an interpreter: evaluation may unfold recursive definitions at most $n$ times. 

Figure \ref{def:worst-case-pure-eval} lists the rules of pure evaluation, they are conventional rules that can be found in most call-by-value calculi.
Similar to the value judgment, the evaluations of $\delay e$ are defined inductively, where 
we evaluate inside the constructor recursively. If $n$ is $0$, $\delay e$ then becomes a "thunk" that rejects further evaluation.
Meanwhile, the rules for the $\circledast$ operator follow the same pattern, creating a thunk for function application at depth 0.
Lastly, the \textsc{E-Val} rule evaluates a value at depth $n$ to itself, as the base case for other evaluations. From Lemma \ref{lem:worst-case-value-closure},
we can derive that a value will remain unchanged if we decrease the depth.

\subsubsection{Forcing Evaluation}
The forcing evaluation judgment $e \Downarrow^{c}_{n,i} v$ relates a term $e$ of type $\tmonad{I}{\tau}$
to a value $v$ of type $\tau$, it is indexed additionally by the time $i$ to interpret the cost of evaluation from a symbolic cost to a real cost $c$.

Figure \ref{def:worst-case-forcing-eval} gives all the forcing evaluation rules. In particular, only constructors of monads have forcing evaluation. \textsc{E-Tick} gives the time interpretation of
$I$ in the term $\tick{I}$ and reduces it to $\langle \rangle$, hence the evaluation costs $I(i)$. The \textsc{E-Return} rule specifies that $\ret e$ just gives the pure evaluation result of 
$e$ with 0 cost. \textsc{E-Bind} composes two monadic computations $e_1$ and $e_2$ and sums the costs, it first evaluates $e_1$ purely to reach its monadic constructor, then 
continues to force it, and similarly for $e_2$. Of greater interest is the $\text{E-Prepay}$ rule, evaluating $\pull e$ requires at least one amount of "fuel" to reduce inside the 
$\delay$ constructor. As we pass through a $\delay$, $i$ also increments by one locally in order to assign the future cost value.
For example, $\pull \tick{I} \Downarrow^{I(i+1)}_{n, i} \delay \langle\rangle$, the cost is $I(i+1)$. From Definition \ref{def:time-indices}, this aligns with the typing cost $\mathsf{S}(I)$'s interpretation.

There is no rule for evaluating a term typed $\triangleright \tmonad{I}{\tau}$ using $n$, this is to keep the laziness of cost effects:
If a computation is delayed, its cost should not be incurred now. To demand the data inside a delayed monadic computation, the only way is to use $\pull$ and pay for
the corresponding future cost.



\begin{figure}[!htbp] 
  \small
  \mprset{sep=1em,andskip=1.5em plus 0.5fil minus 0.5em}
  \renewcommand{\MathparLineskip}{\lineskiplimit=0.6em\lineskip=0.7em plus 0.1em}
  \begin{mathpar}
  \inferrule*[right=E-Return]
  {e \Downarrow_n v}
  {\ret e \Downarrow_{n,i}^0 v}

  \inferrule*[right=E-Tick]
  { }
  {\tick{ I} \Downarrow_{n,i}^{ I(i)} \langle \rangle}
  \\

  \inferrule*[right=E-Bind]
  {
    e_1 \Downarrow_n v_1 \quad 
    v_1 \Downarrow_{n,i}^{c_1}v_1'
    \quad
    e_2[v_1'/x] \Downarrow_n v_2
    \quad
    v_2 \Downarrow_{n,i}^{c_2} v_2'
  }
  {
    \bind{x}{e_1}{e_2}
    \Downarrow_{n,i}^{c_1+c_2}
    v_2'
  }
  \\

  \inferrule*[right=E-Prepay]
  {
    e \Downarrow_{n+1} \delay v
    \quad

  }

  }
\end{mathpar}

  \label{def:worst-case-forcing-eval}
\end{figure}

Now we can examine Theorem \ref{thm:worst-case-soundness}, which formulates the soundness of $\lambda^g_{\mathsf{worst}}$.
The theorem states that if $e$ is a closed term that has a symbolic cost $I$ designated by its type, and if it can be evaluated purely into a value $v$, then 
continue forcing it incurs a semantic cost $c$, this cost will be bounded by the interpretation of $I$ based on current time 
$i$, i.e. $c \leq I(i)$.
\begin{thm}[Soudness of $\lambda^g_{\mathsf{worst}}$]
\label{thm:worst-case-soundness}
$\\$ For all $e, v, I,c,\tau \in Type$ and $n, i \in \mathbb{N}$, if $\,\hastype{}{e}{\tmonad{ I}{\tau}}$, $e \Downarrow_n v$ 
and $v \Downarrow^c_{n, i} v'$, then $c \leq  I(i).$ 
\end{thm}
The soundness theorem is different from $\lambda$-amor since our cost needs to be interpreted by the logical time, 
$\lambda$-amor instead directly uses $I$ as the bound since its semantic cost has the same form as the cost approximated by the type.
The proof of this theorem will be discussed in the next chapter.

\section{Program Examples}
\label{sec:worst-case-program-examples}
In this section, we present several programs in $\lambda^g_{\mathsf{worst}}$ that demonstrate the expressiveness of the 
calculus and its type-based cost analysis features.

\subsection{Guarded Recursion}
To express guarded recursive functions, a fixed point combinator is required. Here we present the guarded version of Turing's fixed point combinator 
described in \citep{cloustonGuardedLambdaCalculusProgramming2017a}.

\begin{defn}[Guarded Fixed point] The fixed point is derived as follows:
\begin{align*}
  \mathsf{Rec}
    &\triangleq
      \mu\alpha.
      \bigl(\triangleright\alpha
        \to(\triangleright\tau\to\tau)\to\tau\bigr), \\
  \theta
    &\triangleq
      \tlam{y}{\tlam{f}{
        f\bigl(
          (\delay(\tlam{z}{\unfold z}))
          \circledast y
          \circledast(\delay y)
          \circledast \delay f
        \bigr)}} \\
    &: \triangleright\mathsf{Rec}
       \to(\triangleright\tau\to\tau)\to\tau, \\
  \fix &\triangleq \theta (\delay(\fold\theta))
    :(\triangleright\tau\to\tau)\to\tau.
\end{align*} 
\end{defn}

Given a function $f$, according to \textsc{E-App}, $\fix f$ reduces to
\[
          f\bigl(
            (\delay(\tlam{z}{\unfold z}))
            \circledast (\delay \fold \theta)
            \circledast(\delay \delay \fold \theta)
            \circledast \delay f
          \bigr) 
\]
From \textsc{E-NappZero} and \textsc{E-NappInd}, no matter what $n$ we are given for evaluation, it then reduces to 
\[
  f\bigl(
            \delay((\tlam{z}{\unfold z}) \,
            \fold \theta \,
            (\delay \fold \theta)\,f)
          \bigr)
\]
Suppose $n=1$, we can reduce inside the $\delay$. 
The inner application gives $\unfold \fold \theta$, it then gets eliminated to $\theta$ by $\textsc{E-Unfold}$.
Therefore, the whole expression becomes 
\[
  f (\delay (\theta(\delay \fold \theta)f)) 
\]
This expression is exactly $f (\delay \fix f)$. 
Since our call-by-value semantics evaluate arguments eagerly, different $n$ results in different expansions:
\begin{align*}
  &n = 0: \fix f  \\
  &n = 1: f (\delay \fix f)   \\
  &n = 2: f (\delay f (\delay\fix f)) \\
  &n = 3: f (\delay f (\delay f (\delay \fix f))) \\
  &\vdots
\end{align*}
However, when $n = 0$, $\fix f$ will reduce to the ugly result as the base case: 
\[  f\bigl(
            \delay((\tlam{z}{\unfold z}) \,
            \fold \theta \,
            (\delay \fold \theta)\,f)
          \bigr)\]
This is to retain the unevaluated term under $\delay$ to allow further evaluation, as mentioned before.

\subsection{Stream Processing}
We can now use the fixed point combinator to build guarded streams and derive cost analysis for 
ordinary stream processing functions.

Firstly, we define the guarded stream type and its standard functions:
\[
  \tstr{\tau}
  \triangleq
  \mu\alpha.(\tau\times\triangleright\alpha).
\]
\begin{align*}
  (::) &\triangleq \tlam{x}{\tlam{s}{\fold\tuple{x}{s}}}
  &&: \tau\to\triangleright\tstr{\tau}\to\tstr{\tau}, \\
  \head &\triangleq \tlam{s}{\mathsf{fst}\,(\unfold s)}
  &&: \tstr{\tau}\to\tau, \\
  \tail &\triangleq \tlam{s}{\mathsf{snd}\,(\unfold s)}
   &&: \tstr{\tau}\to\triangleright\tstr{\tau}.
\end{align*}
Here we overload the syntax, using the same notation (::) as list cons to construct streams.

Based on the stream constructors, we can define a family of functions that enables us to observe a stream deeper:
\begin{flalign*}
  &\quad\mathsf{nth}_n : \tstr{\tau} \to \triangleright^n\tau && \\
  &\quad\mathsf{nth}_0 \triangleq \tlam{s}{\head s} && \\
  &\quad\mathsf{nth}_{n+1} \triangleq \tlam{s}{(\delay \mathsf{nth}_n)\circledast(\tail s)} &&
\end{flalign*}
The functions are defined inductively for convenience instead of listing all of their definitions, and $n$ 
is hardcoded as the order number of a function. In particular, 
the base case just returns the current head, and the inductive case calls previous functions on the stream tail to demand 
the next element. Since subsequent elements are guarded, the number of ``later''s in the type signature follow the exact position of the element in the stream.

We will focus on the $\tstr{\tmonad{I}{\tau}}$ type for our later examples,
it denotes a stream of computations, where each element takes $I(i)$ cost to evaluate.
For example, we can construct a stream whose cost varies for each element:
\begin{flalign*}
  &\quad\mathsf{tickTime} : \tstr{\tmonad{\clk}{\mathbf{1}}} && \\
  &\quad\mathsf{tickTime} \triangleq \fix\lambda x.\, \tick{\clk} :: x &&
\end{flalign*}
For each element, this stream simply ticks the cost representing the time.
Table \ref{fig:ticktime-costs} shows the cost of each element. 
Intuitively, each cost aligns with the time and its element position, which can be thought of as modelling the cost 
of traversing the stream.

Operationally, we can define a family of functions that allow us to evaluate the $ n$-th element of a stream, which is similar to the $\mathsf{nth}$ function:
\begin{flalign*}
&\quad\mathsf{prepayNth}_n : \forall I.\,\tstr{(\tmonad{I}{\tau})} \to \tmonad{\mathsf{S}^n(I)}{(\triangleright^n\tau)}, &&\\
&\quad\mathsf{prepayNth}_0 \triangleq \Lambda.\tlam{s}{\head s}, &&\\
&\quad\mathsf{prepayNth}_{n+1} \triangleq \Lambda.\tlam{s}{\pull((\delay (\mathsf{prepayNth}_n\,[\,]))\circledast(\tail s))} &&
\end{flalign*}
The symbolic cost $\mathsf{S}^n(I)$ records the amount of increment needed for the current time 
to obtain the delayed cost. Moreover, the index $I$ is polymorphic and can take streams of arbitrary cost.
However, there is no polymorphism for the number of nested ``laters''($\triangleright^n\tau$) in our type system, we 
choose the index that is equal to $n$ for $\mathsf{S}^n(I)$.

Ordinary element-wise stream processing functions can be defined easily:
\begin{flalign*}
&\quad\mathsf{mapC}: \forall I_1, I_2.\,(\tau \to \tmonad{I_1}{\tau}) \to \tstr{\tmonad{I_2}{\tau}} \to \tstr{\tmonad{(I_1 + I_2)}{\tau}} &&\\
&\quad\mathsf{mapC} \triangleq \fix\lambda m.\Lambda.\Lambda.\lambda f.\lambda s.&&\\
&\qquad(\bind{x}{\head s}{f\; x}) :: (m\,[\,]\,[\,]\circledast \delay f \circledast\tail s) &&
\end{flalign*}
$\mathsf{mapC}$ is the cost-aware version of the common stream mapping function.
The function $f$ has type $\tau \to \tmonad{I_1}{\tau}$, which is the standard type of encoding 
a computation that does some work to process its input. For streams, we need to first force the head computation
and feed its result into $f$, and the 2 separate costs will be added by $\mathsf{bind}$.

Likewise, we can define a $\mathsf{zipWithC}$ as follows:
\begin{flalign*}
&\quad\mathsf{zipWithC}: \forall I_1, I_2, I_3.\;(\tau_1\to\tau_2\to\tmonad{I_3}{\tau_3}) &&\\
&\qquad\to\tstr{\tmonad{I_1}{\tau_1}}\to\tstr{\tmonad{I_2}{\tau_2}}
    \to\tstr{\tmonad{(I_1+I_2+I_3)}{\tau_3}} &&\\
&\quad\mathsf{zipWithC}\triangleq\fix\lambda z.\Lambda.\Lambda.\Lambda.
  \lambda f.\lambda s_1.\lambda s_2. &&\\
&\qquad E_1::(z\,[\,]\,[\,]\circledast \delay f \circledast\tail s_1\circledast\tail s_2) &&\\
&\qquad\textbf{where }E_1\triangleq
  \bind{h_1}{\head s_1}{\bind{h_2}{\head s_2}{f\,h_1\,h_2}}. &&
\end{flalign*}

The function $f$ now requires one element of each input stream, and the final cost accounts for three computations: evaluating the two heads 
and processing their values with $f$.

\subsection{Primitive Recursion}
Functions like $\mathsf{mapC}$ and $\mathsf{zipWithC}$ are standard examples for demonstrating co-recursion since they continue to perform element-wise operations on streams 
and never stop. On the other hand, we can also express (primitive) recursions that will eventually terminate, with the 
help of indexed types.

Firstly, we can derive a size-indexed natural number type using lists: 
\[\mathsf{Nat}(I) \triangleq L^I\textbf{1}\]
The natural number type is just a list of units, where the data stored is irrelevant. 

Next, we define the $\mathsf{Colist}$ type, which represents a possibly infinite guarded list:
\[
  \colist{\tau} 
  \triangleq
  \mu\alpha.\textbf{1} + (\tau\times\triangleright\alpha).
\]
\begin{align*}
  (::) &\triangleq \tlam{x}{\tlam{s}{\fold(\mathsf{inr}(\tuple{x}{s}))}}
  &&: \tau\to\triangleright\colist{\tau}\to\colist{\tau}, \\
  (null) &\triangleq \fold(\mathsf{inl}\,\langle\rangle)
  &&: \colist{\tau}
\end{align*}
A co-list is almost the same as a guarded stream, except that it can terminate with a unit value, represented by the ``$null$'' constructor.
Similar to stream, we also use the notation (::) as the cons constructor.

After constructing the two types, we can use them to define functions that consume a fixed-length prefix of a stream.
For example:
\begin{flalign*}
&\quad\mathsf{takeC}:\forall J, I.\;\mathsf{Nat}(J) \to \tstr{\tmonad{I}{\tau}} 
  \to \tmonad{(\textstyle\sum_{\kappa<J}\mathsf{S}^\kappa I)}{\colist{\tau}} &&\\
&\quad\mathsf{takeC} \triangleq \fix \lambda f.\Lambda.\Lambda.\lambda n.\lambda s. &&\\
&\qquad\mathsf{match}\;n\;\mathsf{with} &&\\
&\qquad\mid\;nil \mapsto \ret (null) &&\\
&\qquad\mid\;-::n'\mapsto \bind{t}{\pull((f\;[\,]\;[\,])\circledast\tail s\circledast\delay n')}{} &&\\
&\qquad\qquad\bind{h}{\head s}{}\ret(h::t) &&
\end{flalign*}

The $\mathsf{takeC}$ function copies the first $J$ elements of the input stream into a co-list. It forces each element and stores their results,
hence the final type is a monad that sums all the costs and returns a pure co-list. 

Since $\mathsf{Nat}(J)$ is indeed a list, we can pattern match on 
it to achieve the effect of recursion on natural numbers. In the base ($nil$) case, the function returns $null$ to end the co-list; $\mathsf{ret}$ gives cost 0, which is consistent with the type signature since 
$\textstyle\sum_{\kappa<0}\mathsf{S}^\kappa I = 0$. In the recursive case, we use $\pull$ to access the recursive call that is originally guarded, 
bind its result and the head computation to construct the final co-list. Note that the recursive call's type is also polymorphic, the natural number's size is instantiated with $J-1$.
As a result, the cost of the $\pull$ is $\mathsf{S}(\textstyle{\sum}_{\kappa<(J-1)}\mathsf{S}^{\kappa} I)$, and the final cost is $\mathsf{S}(\textstyle{\sum}_{\kappa<(J-1)}\mathsf{S}^\kappa I) + I$.

From the sort rule of bounded sum, we know $J$ is a time-independent natural number, then we can rewrite the cost to match that presented in the type signature:
\[
\begin{aligned}
\mathsf{S}\Bigl(\sum_{\kappa<J-1}\mathsf{S}^\kappa I\Bigr) + I 
  &= \Bigl(\sum_{\kappa<J-1}\mathsf{S}^{\kappa+1} I\Bigr) + I && (\text{by Lemma \ref{lem:shif-dist} and } \mathsf{S}(\mathsf{S}^{\kappa}) = \mathsf{S}^{\kappa+1})\\
  &= \Bigl(\sum_{\kappa<J-1}\mathsf{S}^{\kappa+1} I\Bigr) + \mathsf{S}^0 I && (I = \mathsf{S}^{0}I) \\
  &= \sum_{\kappa<J}\mathsf{S}^\kappa I && (\text{reindex } J-1 \text{ and } \kappa +1) 
\end{aligned}
\]

Overall, indexed types such as $\mathrm{Nat}(I)$ let us process a finite prefix
of an infinite type like the guarded stream, and the total cost is a finite sum. Since
a stream cannot end, the results are collected in a type that can terminate,
such as a co-list, which also agrees with the structure of guarded recursive types.
